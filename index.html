04 / CONCEPTO

¿Qué es Arquitectura de la Información?

La estructura invisible que hace comprensible un producto digital.

La Arquitectura de la Información (AI) consiste en organizar, nombrar y conectar contenidos para que las personas sepan dónde están, qué pueden encontrar y cómo llegar a ello.

Organización

Agrupar contenidos que pertenecen a una misma categoría.

Etiquetado

Utilizar nombres comprensibles para cada sección.

Navegación

Definir caminos claros entre páginas y funciones.

Búsqueda

Facilitar la localización de información concreta.

07 / ESTRUCTURA

Cuatro formas de organizar contenido

No existe una única estructura correcta para todos los productos.

Jerárquica

Inicio → categorías → subcategorías. Frecuente en portales educativos.

Secuencial

Paso 1 → paso 2 → confirmación. Útil para formularios y compras.

En red

Múltiples conexiones entre contenidos. Habitual en enciclopedias.

Por facetas

Filtros por fecha, precio, tipo o categoría. Común en catálogos.

La estructura depende de las tareas y del volumen de información.

13 / DEFINICIÓN

¿Qué es UX?

UX significa User Experience: experiencia de usuario.

La experiencia de usuario abarca lo que una persona percibe al interactuar con un producto o servicio: si entiende qué hacer, si logra su objetivo, cuánto esfuerzo requiere y qué sensación le deja.

Útil

Resuelve una necesidad real.

Usable

Permite completar tareas con facilidad.

Comprensible

Comunica estados, opciones y consecuencias.

Confiable

Genera seguridad y expectativas consistentes.

14 / DIFERENCIAS

UX no es lo mismo que UI

Una se ocupa de la experiencia completa; la otra, de la interfaz visible.

UX · EXPERIENCIAEl recorrido

Investigación, tareas, organización, flujos, pruebas y mejora.

UI · INTERFAZLa expresión visual

Tipografía, color, iconos, botones, composición y estados.

Una interfaz visualmente atractiva no garantiza que sea fácil de usar; UX y UI se complementan.

Investigar: comprender necesidades. Definir: priorizar problemas. Organizar: estructurar contenido. Prototipar: hacer tangible la idea. Probar: observar el uso. Iterar: mejorar con lo aprendido.

El proceso no siempre es lineal: se puede regresar a etapas anteriores.
16 / INVESTIGACIÓN

Antes de asumir, preguntar

Las decisiones de UX se apoyan en evidencia sobre personas y tareas.

Entrevistas

¿Qué intentas lograr? ¿Qué te frustra? ¿Cómo lo resuelves hoy?

Observación

Mirar cómo se completa una tarea sin guiar cada clic.

Encuestas

Identificar patrones en grupos más grandes.

Analítica

Detectar abandonos, errores y rutas frecuentes.

Ejemplo: “los estudiantes nunca usan la biblioteca” no es una conclusión; primero hay que averiguar por qué.

22 / HEURÍSTICAS

Buenas interfaces hablan con claridad

Principios prácticos para detectar problemas de uso.

Visibilidad del estado

Mostrar carga, progreso, éxito y errores.

Consistencia

Usar patrones similares para acciones similares.

Prevención de errores

Evitar decisiones confusas o destructivas.

Control del usuario

Permitir cancelar, regresar o corregir.

Ejemplo: después de subir un archivo, mostrar “Entrega recibida” y el nombre del documento.
23 / ACCESIBILIDAD

Diseñar para más personas

La accesibilidad debe pensarse desde el inicio.

Contraste

El texto debe distinguirse del fondo.

Teclado

Las funciones deben poder utilizarse sin ratón cuando corresponda.

Texto alternativo

Las imágenes informativas necesitan descripciones.

Movimiento

Las animaciones no deben dificultar la comprensión; respeta movimiento reducido.

En Animación Multimedia: el movimiento debe comunicar, no distraer ni impedir que alguien complete una tarea.
24 / ANIMACIÓN

¿Cuándo aporta valor una animación?

El movimiento puede explicar relaciones y confirmar acciones.

ARCHIVO
Observa cómo el movimiento conecta la acción con el resultado.

Una transición útil comunica continuidad, jerarquía o retroalimentación. Un movimiento decorativo excesivo puede aumentar la carga cognitiva.

25 / CASO INTEGRADOR

Rediseñemos una entrega académica

Del problema observado a una solución justificable.

PROBLEMA

“No sé si entregué mi proyecto”

El sistema recibe el archivo, pero no muestra confirmación.

PROPUESTA

Confirmación explícita

Nombre del archivo, fecha, estado y opción de reemplazar.

CRITERIO UX

Menos incertidumbre

La interfaz comunica el resultado y permite corregir.

Discusión: ¿qué cambiarías en la arquitectura? ¿Qué cambiarías en la interfaz?
